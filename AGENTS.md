# AGENTS.md

Read this before adding or changing a skill. The build contract is [SPEC.md](SPEC.md). [CLAUDE.md](CLAUDE.md) points here.

`gstin-validator` is the reference skill. Copy its shape. Do not reimplement a checksum, a money helper, or a date rule that already lives in `lib/`.

## Who edits what

Agent 0 (this scaffold) owns `lib/`, `tools/`, `README.md` prose, `.claude-plugin/marketplace.json`, `skills.sh.json`, `CHANGELOG.md`, and `.github/workflows/`. Other skills rebase onto that.

A skill PR may touch only:

- `skills/<skill-name>/`
- `evals/<skill-name>/`
- keys it owns in `rules/<domain>.json`

One skill per branch, named `feat/<skill-name>`. No force-push to `main`.

The generated skills table is the exception inside `README.md`. Run `npm run readme` and commit the marker block so CI stays green. Do not rewrite the surrounding prose. Do not add yourself to `marketplace.json`; Agent 0 adds `./skills/<skill-name>` when the skill is merged. `skills.sh.json` already lists the 13 planned names.

## Layout you must ship

```
skills/<skill-name>/
  SKILL.md
  scripts/<tool>.mjs
  scripts/lib-manifest.json
  scripts/_lib/          # generated by sync-lib; do not hand-edit
  scripts/_rules/        # generated by sync-lib; do not hand-edit
  references/sources.md
  tests/<name>.test.mjs
evals/<skill-name>/evals.json
```

Test files are `skills/<skill-name>/tests/*.test.mjs` and use `node:test` plus `node:assert/strict`. `npm test` is `node --test`. Shared helper tests live next to `lib/` as `lib/*.test.mjs`. Do not put skill tests anywhere else.

## Shared helpers — copy, don't import the repo root

Installers copy only the skill folder. Import from `./_lib/`, never from `../../../lib/`.

Declare copies in `skills/<name>/scripts/lib-manifest.json`:

```json
{ "lib": ["money.mjs", "fy.mjs", "rules.mjs", "disclaimer.mjs"], "rules": ["gst.json"] }
```

Then run `node tools/sync-lib.mjs`. CI runs it with `--check` and fails if a copy drifts. List every module you import, including modules those files import (`gstin.mjs` needs `rules.mjs` and `disclaimer.mjs`).

| Module | Use |
| --- | --- |
| `lib/money.mjs` | `parseAmount`, `formatMinor`, `pct`. Minor units are bigint. 18% is `1800` basis points. Half-up, away from zero. |
| `lib/fy.mjs` | `fyOf`, `parseFy` (`2025-26` and `2025-2026`), `addMonths` (clamps to month end), `istDate`. |
| `lib/rules.mjs` | `loadDomain`, `ruleById(domain, id, onDate)`, `needsConfirm`. |
| `lib/disclaimer.mjs` | `disclaimer(asOf)`, `CONFIRM_SENTENCE`. |
| `lib/gstin.mjs` | `validateGstin`, `checkChar`, `generateSyntheticGstin`. |
| `lib/verhoeff.mjs` | `verhoeffValid`, `verhoeffCheckDigit`, `normalizeDigits`, `generateSynthetic`, `leadingDigitFinding`. |
| `lib/vendor/qrcodegen.mjs` | Nayuki QR, MIT header kept. `qrcodegen.QrCode.encodeText(text, qrcodegen.QrCode.Ecc.MEDIUM)`. |

`leadingDigitFinding` returns `confirm: true` for an Aadhaar-shaped number that starts with 0 or 1. That rule is unpublished by UIDAI. Warn. Do not reject on it alone. `999999999999` starts with 9 and does not trip it.

## SKILL.md

Frontmatter, then these sections in order: When to use, Quick start, Rules, Edge cases, Disclaimer. Body under 500 lines.

```yaml
---
name: gstin-validator
description: >-
  What it does, in keywords an agent can match. Use when ...
license: MIT
compatibility: Requires Node.js 20 or newer. No network and no runtime dependencies.
metadata: { version: "0.1.0", rules-as-of: "2026-11-01", jurisdiction: "IN" }
---
```

`name` matches the folder: 1–64 chars, `[a-z0-9-]`, no leading, trailing, or doubled hyphen. `description` is 1–1024 chars and contains `Use when`. `metadata` values are strings.

## Scripts

Invoke as `node scripts/<file>.mjs --json '<input>'`. Print one JSON object to stdout. Exit `0` when valid, `1` when invalid, `2` on a usage error. No network. The future IFSC `--lookup` flag is the only exception, and it must be opt-in in `skills/indian-id-validators/scripts/ifsc-lookup.mjs`. Tests mock `fetch` and never call it.

Every tax, legal, or payment result includes `disclaimer` from `disclaimer(asOf)` and `confirm`. If any rule you applied has `verified: false`, set `confirm: true` and include the text `Confirm with the official source before relying on this.`

## Rules data

`rules/<domain>.json` uses schema 1. Each rule has `id`, `value`, `unit`, `effectiveFrom`, `effectiveTo` (`null` or a date), `source` (https only), `verified`, and `note`. Scripts read values with `ruleById`. Pass a date. Do not hardcode a rate, a code list, or a deadline that belongs in JSON.

`references/sources.md`: every `- ` bullet is a markdown link whose target is https, or it contains the literal tag `UNVERIFIED`. If a bundled rule has `verified: false`, the file must contain `UNVERIFIED`.

## Coding rules that CI checks

- Node 20+, ESM `.mjs`, no runtime dependencies.
- Money: no `parseFloat(` and no `* 100` in `lib/*.mjs` or `skills/*/scripts/*.mjs` (not under `_lib`). Scale with basis points and `pct`.
- Dates: `YYYY-MM-DD` strings. IST is UTC+05:30 with no DST. Never `new Date('YYYY-MM-DD')`.
- Input: trim, NFKC, strip spaces and hyphens for IDs, uppercase PAN / GSTIN / IFSC, reject zero-width and bidi controls, refuse inputs over 10 KB. Anchored regexes only, no nested quantifiers. `compileAnchored` enforces that for rule patterns.
- Comparisons of MACs: `crypto.timingSafeEqual` only after the buffers have the same length. Do not normalise hex case unless the vendor says to.
- The rupee sign is `₹` (U+20B9). Do not write `Rs.` unless the user asked.
- Tests are offline. Synthetic IDs only. The only real GSTINs allowed are the public ones in SPEC §1.1, and only as checksum vectors. `tools/scan-aadhaar.mjs` fails on a Verhoeff-valid 12-digit number that is not in `tools/aadhaar-allowlist.txt`.
