# Sources

Rules as of 2026-11-01. A bullet is either a page that was opened or an explicit UNVERIFIED tag.

- [UPI Linking Specifications v1.6 (November 2017), public mirror](https://www.labnol.org/files/linking.pdf) — opened 2026-11-01. `pa` and `pn` are mandatory. `cu` is only INR. `mode` is mandatory (`00` default, `01` QR, `02` secure QR, `04` intent, `05` secure intent, `06` NFC, `07` BLE, `08` UHF, `15` SEBI, `16`–`18` future). `tr` is mandatory for a merchant transaction and for a dynamic URL. If `am` is absent the amount is editable. A space is `%20`, not a plus. `sign` is mandatory in the spec; `orgid` is `000000` for a merchant-created intent. This skill does not sign. The NPCI-hosted PDF path was not available when this was checked; the mirror is the NPCI text.
- [NPCI UPI OC 185B, 28 Aug 2025](https://www.npci.org.in/uploads/UPI_OC_No185_B_FY_2025_26_Addendum_to_OC_185_A_Implementation_of_higher_per_transaction_limit_for_specific_categories_in_UPI_ba517a0902.pdf) — opened 2026-11-01. Addendum to OC 185A. Comply by 15 Sep 2025. Higher per-transaction ceilings for verified merchants in the annexure (capital market, insurance, Government e-Marketplace, travel, credit-card bills, collections, jewellery, and the purpose-qualified rows). P2P per-transaction limit continues under the extant guidelines. Banks may set a lower internal limit. The annexure was read from the PDF text extraction; MCC digits are those in that annexure.
- [RBI Statement on Developmental and Regulatory Policies, 9 Apr 2025](https://www.rbi.org.in/Scripts/BS_PressReleaseDisplay.aspx?prid=60178) — opened 2026-11-01. P2P UPI stays capped at ₹1 lakh. The general UPI transaction amount is ₹1 lakh except specific P2M cases. Banks keep discretion inside the announced ceilings.
- VPA grammar `^[a-zA-Z0-9.\-_]{2,256}@[a-zA-Z][a-zA-Z0-9]{1,64}$` — UNVERIFIED. v1.6 does not publish a VPA grammar. The script sets `confirm` true.
- Amount greater than zero and at most two decimal places — UNVERIFIED. v1.6 says "decimal format" only. Enforced as a safe default. The script sets `confirm` true.
- `mc` restricted to four digits — UNVERIFIED. v1.6 says to pass `mc` as it is. The samples are four digits. The script sets `confirm` true.
- `purpose` — UNVERIFIED and not a v1.6 parameter. The script rejects it. OC 185B rows that need a purpose code cannot be selected from the link, so those MCCs use the ₹1 lakh P2M default.
