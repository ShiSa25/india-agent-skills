# Sources

Rules as of 2026-11-01. A bullet is either a page that was opened or an explicit UNVERIFIED tag.

- [Aadhaar Act, 2016, as amended](https://uidai.gov.in/images/Aadhaar_Act_2016_as_amended.pdf) — opened 2026-11-01. Section 3(4) says the Aadhaar number is twelve digits. Section 4(2) says it is random and bears no relation to the holder's attributes. Section 29 restricts sharing of core biometric information and other identity information, and restricts public display of the Aadhaar number, demographic information, and photograph. Sub-sections (3) and (4) are the text substituted by Act 14 of 2019 with effect from 25 Jul 2019.
- Leading digit 0 or 1 — UNVERIFIED. UIDAI does not publish this restriction. The script warns and does not reject. `999999999999` starts with 9 and does not trip it. SPEC §1.11's parenthetical says that specimen trips the warning; this pack follows `lib/verhoeff.mjs`.
- [UIDAI dos and don'ts for requesting entities, 31 Oct 2022](https://www.uidai.gov.in/images/DosandDonots_for_Requesting_Entities.pdf) — mask the first 8 digits of an Aadhaar number on a stored copy. Display is `XXXX XXXX` plus the last 4.
- [UIDAI Circular No. 14 of 2025, 4 Nov 2025](https://uidai.gov.in/images/Circular-No.14_of-2025.pdf) — opened 2026-11-01. Requesting entities must store Aadhaar numbers and connected Aadhaar data only in an Aadhaar Data Vault, and must use a reference key elsewhere. Hashing the Aadhaar number is not allowed as that key. The circular supersedes the 25 Jul 2017 vault circular. SPEC §1.11 said to mark the vault details `verified: false` because the site was flaky; this PDF was opened, so the storage sentence is `verified: true`. Hosting choices in the same circular (GCC, HSM, AES) are not copied into the rule value.
- [UIDAI authentication page](https://uidai.gov.in/en/authentication) — opened 2026-11-01. A VID is a temporary, revocable 16-digit random number mapped to the Aadhaar number, and an agency should not store it. The page does not publish a checksum. The old VID FAQ index returns HTTP 404, so it is not cited.
- VID mask `XXXX XXXX XXXX` plus the last 4 — UNVERIFIED. The 12-digit mask is the UIDAI first-8 redaction. Extending it to 16 digits is this pack's display. The authentication page does not publish a mask template, so a VID result sets `confirm` true.
- [Aadhaar Act section 3(3)](https://uidai.gov.in/images/Aadhaar_Act_2016_as_amended.pdf) — the Authority issues the number. The Verhoeff tables used here live in `lib/verhoeff.mjs` (copied to `scripts/_lib/verhoeff.mjs`). A passing check is not issuance. The specimens `234123412346`, `999999999999`, and `123456789010` are the synthetic values in SPEC §1.11.
- The shared `rules/ids.json` copy also contains UNVERIFIED rows this skill does not decide: the mobile `6-9` pattern, the `1800` toll-free prefix, PIN zone names, and the Razorpay IFSC host. Those belong to `indian-id-validators`.
